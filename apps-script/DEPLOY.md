# 雲端後端部署步驟（只需做一次，約 10 分鐘）

這份文件給**專案擁有者**（資料要存進誰的 Google 帳號，就用誰的帳號做）。
做完之後，巡檢人員不需要 Google 帳號（只要用白名單 email 登入 Cloudflare），資料就會統一進到你的雲端。

```
手機網頁 ──登入──> Cloudflare（catpatrol.a-wen90.workers.dev）──帶 token 代轉──> Apps Script ──> 試算表／Drive
```
Apps Script 網址和 token 只存在 Cloudflare 後台，手機上看不到。

---

## 1. 建立 Apps Script 專案

1. 用你的 Google 帳號登入，開啟 <https://script.google.com/>
2. 左上角點「**新增專案**」
3. 專案名稱點一下改成 `CATPatrol 後端`（左上角預設是「未命名專案」）

## 2. 貼上程式碼並設定 token

1. 編輯器中間預設有一個 `Code.gs`（或 `程式碼.gs`），把裡面的內容**全部刪掉**
2. 打開本資料夾的 [`code.gs`](code.gs)，**全選複製**，貼進編輯器，按 💾 儲存（Ctrl+S）
3. 左邊齒輪 ⚙️「**專案設定**」→ 拉到最下面「**指令碼屬性**」→「**新增指令碼屬性**」：
   | 屬性 | 值 |
   |---|---|
   | `API_TOKEN` | **你自訂的一串長一點的亂碼**（例如 `cp-7Hq2-xR9m-2026`） |

   按「**儲存指令碼屬性**」。這串字等一下要填進 Cloudflare，用來擋掉不相干的人亂送資料。**請記下來。**
   （token 不寫在程式碼裡，之後貼新版程式碼不必再改任何一行。）

## 3. 首次授權並建立試算表

1. 編輯器上方的函式下拉選單，選 **`setup`**
2. 按「**執行**」
3. 第一次會跳出授權視窗：
   - 點「**審查權限**」→ 選你的帳號
   - 出現「Google 尚未驗證這個應用程式」→ 點左下角「**進階**」→「**前往 CATPatrol 後端（不安全）**」
   - （這是你自己寫的程式、只存取你自己的檔案，所以是安全的。這個警告是因為沒有經過 Google 商店審核。）
   - 點「**允許**」
4. 執行完後，下方「執行記錄」會印出兩個網址：
   - 試算表 `CATPatrol_資料庫` — 之後所有巡檢資料都在這
   - 照片資料夾 `CATPatrol_照片` — 之後所有照片都在這
   
   點進試算表確認有 5 個分頁：專案、設備、巡檢紀錄、自訂欄位定義、照片索引。

## 4. 部署成網頁應用程式

1. 右上角「**部署**」→「**新增部署作業**」
2. 左邊齒輪 ⚙️ →選擇類型→「**網頁應用程式**」
3. 設定：
   | 項目 | 要選什麼 | 為什麼 |
   |---|---|---|
   | 說明 | `v1` | 隨意 |
   | 執行身分 | **我（你的信箱）** | 這樣資料才會寫進**你的**試算表 |
   | 誰可以存取 | **所有人** | Cloudflare 代轉時不會帶 Google 登入；靠 TOKEN 擋外人 |
4. 按「**部署**」
5. 複製「**網頁應用程式網址**」，長得像：
   ```
   https://script.google.com/macros/s/AKfycb...../exec
   ```
   **這串網址就是 API 網址。**

> ⚠️「誰可以存取：所有人」不代表任何人都能看到你的資料 —— 程式只接受帶正確 TOKEN 的請求，
> 而且只能新增資料、無法讀取或刪除你的其他檔案。但 TOKEN 請勿公開貼在網路上。

## 5. 填進 Cloudflare

1. 開啟 Cloudflare 後台 → **Workers & Pages** → 點 `catpatrol`
2. **Settings** →「**Variables and Secrets**」→「**Add**」，新增兩筆，Type 都選 **Secret**（加密、之後看不到內容）：
   | Variable name | Value |
   |---|---|
   | `APPS_SCRIPT_URL` | 第 4 步的網頁應用程式網址 |
   | `API_TOKEN` | 第 2 步指令碼屬性 `API_TOKEN` 的值 |
3. 按「**Deploy**」讓設定生效

完成。巡檢人員的手機什麼都不用設定，登入後就能上傳。
（Secret 存在 Cloudflare，之後 GitHub push 重新部署也不會被洗掉。）

## 之後修改程式碼時

改完 `code.gs` 後要重新部署才會生效：
1. 點一下編輯器裡的程式碼，**Ctrl+A 全選 → Delete 刪光**（確定整個檔案是空的），再貼上新程式碼 → 儲存。
   不要貼在舊程式碼下面，否則會出現「Identifier '…' has already been declared」
2. 「部署」→「**管理部署作業**」→ 右上角 ✏️ 鉛筆 →「版本」選「**新版本**」→「部署」

**網址不會變**，Cloudflare 不用重設。（換了 token 才需要同步更新 Cloudflare 的 `API_TOKEN`。）

> **從 v0.3 以前換到 v0.4 時（只做一次）**：程式碼裡不再有 `const TOKEN = …` 那一行，
> 要先照第 2 步第 3 點新增指令碼屬性 `API_TOKEN`，值＝你原本寫在程式碼裡的那串（Cloudflare 不用改）。
> 沒設的話 App 會顯示「雲端還沒設定 token」。

新版程式有新增欄位時，**第一次被 App 呼叫就會自動補上欄位與標題**（v0.3 起），不必再到編輯器跑 `setup()`。
新欄位一律加在最右邊；如果你在試算表最右邊自己加過欄位，換版前先搬開，免得被標題蓋掉
（v0.3：設備分頁 AA–AD、巡檢紀錄分頁 AB–AD；v0.5：設備分頁 AE「固定方式」）。

> **v0.5 換版時會自動改編號（只跑一次）**：相機編號統一成 `CA`＋3 碼（132 → CA132、1 → CA001），
> 記憶卡統一成 `SD`＋3 碼（野12、Wv12 → SD012）。會改設備、巡檢紀錄、照片索引三個分頁，以及照片資料夾名稱。
> **改之前會自動複製一份試算表**，檔名「CATPatrol_資料庫_備份_改編號前_日期」，在你的雲端硬碟裡。
> 改了哪些可以看「專案設定 → 指令碼屬性」的 `IDS_FIX_REPORT`。
> 看不懂的編號（例如夾了別的英文字母）、或設備分頁裡兩列會變成同一個編號的（例如 12 和 CA012 各一列）不會改，
> App 首頁會用紅字列出來（撞號的會寫出跟哪一台撞），請到試算表手動修改。
> 同一台在不同分頁寫法不同（設備寫 96、巡檢紀錄寫 CA96）會直接合併成 CA096。
>
> **v0.6**：相機編號後面的 **N 代表另一批相機**，保留下來並補成 3 碼（10N → CA010N、CA24N → CA024N）。
> 換 v0.6 時會依新規則自動再整理一次（一樣先備份），v0.5 沒改到的 N 編號和 96／135 這類就會改好。
> 換版前最好請大家先把手機上待上傳的資料傳完（晚傳的雲端也會自動轉成新寫法）。
> 之後如果又在試算表手動貼了舊寫法，可在編輯器執行 `fixIds()` 再整理一次（每次執行前也會先備份）。

（若選「新增部署作業」會產生**新網址**，舊網址仍指向舊程式碼 —— 請避免。）

## 設定巡檢人員姓名（白名單分頁）

App 用 Cloudflare 登入的 email 認人，紀錄上的「巡檢人員」顯示這張表裡的姓名（沒設定就顯示 email）：

1. 打開試算表 `CATPatrol_資料庫` →「**白名單**」分頁（新版程式部署後 App 開過一次就會出現）
2. 每人一列：`email`（和 Cloudflare 登入規則裡的一樣）、`姓名`，加入日期與備註可留空
3. 巡檢員下次開 App 就會帶出姓名

新增巡檢員時要做兩件事：Cloudflare Access 規則的 Emails 加上他的 email，這張表加一列姓名。

## 刪除特定設備的測試資料

1. 編輯器裡找到 `deleteDevices` 函式，把第一行 `IDS` 改成要刪的相機編號，例如 `['CA132', '78']`（寫 132、CA132 都可以，不分大小寫）
2. 函式下拉選 **`deleteDevices`** →「執行」
3. 下方執行記錄會列出各分頁刪了幾列、哪些照片資料夾移到垃圾桶，以及找不到的序號
4. 各手機下次開啟 App 時會跟著移除這些設備（還沒上傳的資料不受影響）

## 疑難排解

| 症狀 | 原因與處理 |
|---|---|
| App 顯示「token 不正確」 | Cloudflare 的 `API_TOKEN` 與 Apps Script 指令碼屬性的 `API_TOKEN` 不一致 |
| App 顯示「雲端還沒設定 token」 | Apps Script「專案設定 → 指令碼屬性」沒有 `API_TOKEN`（v0.4 起 token 改放這裡，換版後要新增一次） |
| 存檔時「Identifier '…' has already been declared」 | 新程式碼貼在舊程式碼下面（或貼了兩次）→ 全選刪光、只貼一份 |
| App 顯示「Worker 尚未設定 APPS_SCRIPT_URL / API_TOKEN」 | 第 5 步的兩筆 Secret 沒設，或名稱打錯 |
| App 顯示「Apps Script 回傳的不是 JSON」 | 部署時「誰可以存取」沒選「所有人」 |
| App 顯示「登入已過期」 | 到「同步」分頁按「重新登入」，用白名單 email 收驗證碼 |
| App 顯示「Worker 的 Access 設定…不符」 | 改過 Zero Trust 團隊名稱或重建了 Access 應用程式。未登入時開網站，登入網址的主機名稱＝團隊網域、`kid` 參數＝AUD，更新 `wrangler.jsonc` 的 `ACCESS_TEAM_DOMAIN` / `ACCESS_AUD` 後 push |
| 收不到登入驗證碼 | Access 登入規則的條件要用「Emails」填完整地址（不是「Emails ending in」）；應用程式要勾選 One-time PIN 登入方式 |
| 資料寫到別人的試算表 | 部署時「執行身分」沒選「我」 |
| 想換一個新的試算表 | 專案設定 → 指令碼屬性 → 刪除 `SS_ID` → 重跑 `setup()` |
| 照片沒進 Drive | 檢查 Drive 是否已滿；單張上限約 50MB（App 壓縮後約 300–500KB，正常不會超過） |
